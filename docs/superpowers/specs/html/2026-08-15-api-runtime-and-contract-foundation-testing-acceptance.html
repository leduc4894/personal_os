Testing & acceptance gates

Child spec chỉ hoàn thành khi contract chạy xuyên Python API, committed OpenAPI snapshot và cả hai TypeScript consumers.

Test strategy approved · 2026-08-15

Unit

  • Settings/bind policy
  • Envelope serialization
  • Error-status map
  • Request/trace context
  • OpenAPI normalization

ASGI contract

  • Success + all framework errors
  • UUIDv7 body/header match
  • Production docs absent
  • No wildcard CORS

Integration

  • Current-head readiness
  • DB unavailable/schema drift
  • Liveness during outage
  • Loopback start/stop
  • Pool cleanup

Generated client

  • Byte-identical export
  • Stale diff failure
  • TS strict compile
  • Web transport contract
  • Plugin transport contract

Security regression

  • Header/query/body sentinels
  • No raw exception
  • Server-owned request ID
  • No token/secret/provider text

Definition of done

  1. Shell-only CLI paths still avoid framework imports.
  2. personal-api serve starts through an app factory.
  3. Liveness performs no dependency call.
  4. Readiness checks only PostgreSQL + schema head.
  5. Every HTTP response follows the common envelope.
  6. OpenAPI snapshot and generated types are reproducible.
  7. Web and plugin compile against the same package.
  8. Production exposes no OpenAPI, Swagger or ReDoc.
  9. Sensitive sentinels never reach response or diagnostics.
  10. No auth/sync route or business migration is introduced.
Bounded dependency change: FastAPI/Uvicorn for Python runtime, openapi-fetch for the shared TypeScript client, and openapi-typescript as a development generator. All versions are lockfile-pinned. No new infrastructure service or mutation-testing scope.
