Phase 2 — Event queue, cursor and reconciliation

Watchers reduce latency. Only cursor continuity and manifest reconciliation establish correctness.

Local → server

1. A Vault event marks a local file dirty.

2. SQLite records path, hash, base, stable event ID and retry state before network I/O.

3. Events serialize per source; separate sources may sync concurrently.

4. Preflight returns replay, conflict, excluded, no-change or an upload plan.

5. The entry completes only after the exact canonical outcome is durable.

Server → local

1. Poll events after the last contiguous sequence.

2. Self-origin is a no-op only when local hash and committed outcome match.

3. A remote event applies only when local hash still equals the recorded base.

4. Download to a sibling temporary file, verify, then atomically rename.

5. Advance cursor only after safe apply, no-op, conflict or tombstone handling.

Manifest reconcile run

start run → bind checkpoint and policy revision → upload ordered pages → verify page/final digests → return deterministic actions → apply and resume cursor

Actions: upload, download, apply_tombstone, conflict, no_change or excluded. Vault events observed during a run remain journaled and replay afterward, so reconciliation never freezes the editor.

Reconcile triggers

  • After onboarding or SQLite recovery.
  • Cursor gap, compacted history or invariant mismatch.
  • Scheduled while the app is active, using small mobile batches.
  • Explicit user “Repair sync” command.

Bounded behavior

  • Queue metadata is bounded; content stays in the Vault.
  • Backpressure pauses network work, never editing.
  • No background-task assumption on mobile.
  • Policy deny preserves local content but blocks upload and projection.
