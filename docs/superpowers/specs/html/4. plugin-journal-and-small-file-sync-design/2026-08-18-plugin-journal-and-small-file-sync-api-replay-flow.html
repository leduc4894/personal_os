Phần 3 — Preflight, stream và exact replay

Hai bước; API nhận raw stream ≤16 MiB. Không multipart, không presigned URL.

Happy path + lost response

  1. Plugin → POST /api/sync/journal-events/preflight
    event ID, idempotency key, create/update, source/local identity, base version, normalized locator, SHA-256, size, media type, policy revision.
  2. Server xác thực device, re-enforce policy/base/idempotency và persist operation single_part.
  3. Plugin → PUT /api/uploads/{operation_id}/content
    Access Bearer + raw stream. Server cap theo threshold, spool, verify hash/size và ghi canonical object.
  4. Server transaction chuyển verified receipt thành source/version/sync-event, rồi lưu terminal receipt.
  5. Plugin persist source ID/current version và đặt event committed.

Lost response sau commit

Retry cùng preflight/event/idempotency key. Server trả committed_replay với original receipt. Không tạo operation/source/version mới và không re-upload bytes.

Preflight outcomes

  • committed_replay
  • no_change
  • excluded
  • conflict → blocked
  • single_part_upload

Hard boundaries

  • Server owns threshold, policy, idempotency.
  • Operation binds device + fingerprint + expiry.
  • No R2 key/receipt/provider detail in HTTP.
  • Byte verification precedes PostgreSQL publication.
