Plan A — API-mediated single part

0–16 MiB

Plugin streams bytes to the authenticated API. The API reuses the Phase 1 bounded spool and conditional CAS write. A failed attempt restarts this small upload.

No presigned URL reaches the client.

Plan B — resumable multipart staging

>16 MiB, maximum 100 MiB

Use 8 MiB equal parts except the last with bounded parallelism. Short-lived presigned part URLs target an exact session staging key.

The server verifies staging bytes, streams them through the Phase 1 CAS writer and exact-deletes staging. A bearer URL never targets an existing canonical object.

Multipart lifecycle

created → uploading → uploaded → verifying → promoting → committed

Any stage may become expired, aborted or failed_terminal. Cleanup addresses only the exact staging key registered to that session.

Why this is the safe first release

  • Preserves the Phase 1 immutable CAS guarantees.
  • Mobile retries only failed parts for larger files.
  • Changing the threshold later does not change the client contract.
  • No Worker deployment or routing revision is introduced.

Accepted trade-offs

  • Multipart promotion reads and writes bytes once more.
  • Small failed uploads restart from zero.
  • Staging cleanup needs a narrow exact-delete capability.
  • 16 MiB is an initial operational threshold, not a product invariant.
