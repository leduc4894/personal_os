Response contract & error handling

Một envelope ổn định cho mọi application/health response và lỗi framework. Raw OpenAPI local/test là ngoại lệ tooling duy nhất.

Contract approved · 2026-08-15

Success envelope

{
  "request_id": "uuid-v7",
  "data": {},
  "warnings": [],
  "error": null
}

Error envelope

{
  "request_id": "uuid-v7",
  "data": null,
  "warnings": [],
  "error": {
    "code": "stable_error_code",
    "message": "Safe fixed message",
    "retryable": false,
    "details": {}
  }
}
1 · CorrelateServer tạo UUIDv7; body và X-Request-ID phải giống nhau.
2 · Validatetraceparent và X-Client-Request-ID được xử lý bằng diagnostics contract hiện có.
3 · MapMỗi stable error code có một HTTP status rõ ràng trong bảng ánh xạ đóng.
4 · RedactChỉ field allowlist được vào details; provider exception không bao giờ ra response.

Quy tắc bắt buộc

  • FastAPI validation, unknown route và method-not-allowed đều đi qua cùng envelope.
  • Không suy HTTP status chỉ từ error category; mapping theo từng code để tránh gộp sai semantics.
  • Retryable dependency failure trả 503; business conflict thường là 409; invalid request là 400/422; lỗi không xác định là 500 internal_error.
  • Không phản chiếu secret, raw content, query string, path, provider response hoặc raw exception.
  • Client request ID không bao giờ thay thế request ID do server sở hữu.
Deferred deliberately: auth error codes và mapping cụ thể thuộc child spec Web auth/device authorization.
Tooling exception: /api/openapi.json ở local/test trả raw OpenAPI 3.1 để generator đọc được; middleware vẫn thêm correlation headers. Production route này không tồn tại và trả enveloped 404.
