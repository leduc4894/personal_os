Resolution transaction

bind conflict and observed remote V4 → recheck current and policy → publish local/merged against V4, or accept remote → mark resolved and audit → atomically apply winner

If current advanced beyond V4, resolution is stale and must be reviewed again. “Keep remote” creates no redundant content version; local or merged creates one immutable version linked to the conflict.

Lifecycle conflicts covered

  • Local edit versus remote edit.
  • Local edit versus remote delete.
  • Local delete versus remote edit.
  • Concurrent rename/move or locator collision.

Safety boundaries

  • Candidate objects are not active source versions.
  • Phase 2 does not delete candidate objects; future GC requires retention and reference recheck.
  • Paths, diff text and bytes never enter logs or Temporal history.
  • Conflict resolution uses a new event identity.
